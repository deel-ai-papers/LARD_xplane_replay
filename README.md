# LARD X-Plane Replay

Replay scenarios generated by [LARD](https://github.com/deel-ai/LARD) in X-Plane. For each pose, runner configures aircraft position, attitude, date, time, and camera field of view. It then captures, crops, renames, and stores screenshots.

## Files

| File | Role |
| --- | --- |
| `runScenario.py` | Scenario runner and command-line entry point |
| `runner_config.yaml` | Machine paths, X-Plane connection, capture defaults, and delays |
| `XPlaneConnectX.py` | Supplied X-Plane communication layer; keep unchanged |
| `*.yaml` | LARD scenario files |

## Requirements

- Python 3.9+
- X-Plane 12 running with a flight already started
- X-Plane network access enabled for UDP communication

Install Python dependencies:

```bash
python -m pip install PyYAML Pillow
```

`pygetwindow` is optional. Install it only when using `--close-after-generation`:

```bash
python -m pip install PyGetWindow
```

## Configuration

Edit `runner_config.yaml` before first run. Most users only need to change:

- `paths.scenario_directory`: directory containing scenario YAML files
- `paths.output_directory`: generated image destination
- `paths.screenshot_directory`: X-Plane screenshot directory
- `xplane.ip` and `xplane.port`: X-Plane UDP endpoint
- `delays.*`: loading and screenshot waits

Relative paths are resolved from `runner_config.yaml`, not current terminal directory.

Warning: when `paths.clear_screenshots: true`, runner deletes every file from configured screenshot directory before each scenario.

Scenario `image.width`, `image.height`, `image.fov`, `image.fov_x`, and `image.fov_y` values override capture defaults. Pose time values override `default_time`.

## Usage

Start X-Plane. Start a flight at any airport. Then run every YAML scenario from configured directory:

```bash
python runScenario.py
```

Run one scenario:

```bash
python runScenario.py --scenario "scenarios/CYEG-2-20-12-30__10-smpl__10h40.yaml"
```

Run every scenario from another directory:

```bash
python runScenario.py --scenario-dir "scenarios/validation"
```

Use another configuration file:

```bash
python runScenario.py --config "configs/workstation.yaml"
```

Close X-Plane after generation:

```bash
python runScenario.py --close-after-generation
```

Options can be combined. `--scenario` and `--scenario-dir` are mutually exclusive.

## Output

Each scenario gets its own directory:

```text
output/
└── CYEG-2-20-12-30__10-smpl__10h40/
    ├── CYEG-2-20-12-30__10-smpl__10h40_00.png
    ├── CYEG-2-20-12-30__10-smpl__10h40_01.png
    └── ...
```

Image count determines zero-padding width. Runner center-crops screenshots to scenario dimensions.

## Scenario format

Minimal structure:

```yaml
image:
  width: 1024
  height: 1024
  fov_x: 60.0
  fov_y: 60.0

poses:
  - airport: CYEG
    runway: "2"
    pose:
      - -113.51948  # longitude, degrees
      - 53.37619    # latitude, degrees
      - 1010.36     # altitude MSL, metres
      - -149.64     # true heading, degrees
      - 87.63       # pitch, degrees; we sends pitch - 90 to X-Plane
      - -1.54       # bank (result from roll), degrees
    time:
      minute: 0
      hour: 11      # local solar time; converted to UTC from longitude
      day: 1
      month: 7
```

## Execution details

- Airport change → `delays.airport_change_seconds`
- Runway change within same airport → `delays.runway_change_seconds`
- Same runway → `delays.same_runway_seconds`
- Screenshot command wait → `delays.screenshot_seconds`
- View mode → forward view with no cockpit equipment
- Simulator → paused during long position jumps

## Known limitations

- Camera window width and height DataRefs may not resize X-Plane. Scenario run compensates field of view, then center-crops screenshots.
- X-Plane window must be at least as large as requested output dimensions.
- Local-to-UTC conversion uses longitude only. It does not model legal time zones or daylight-saving time.
- X-Plane date uses existing approximation: `(month - 1) * 30 + day`.
- Every file in the XPlane screenshot directory is erased when launching a new scenario
